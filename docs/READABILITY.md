# 분석 모듈·모의고사의 가독성 기준

대상 독자는 데이터 분석을 전공했지만 주택·물류·제조·보험·스포츠 등 해당 업무의 배경은 모르는 학습자입니다. 통계 기법은 분석 목적에 연결해 설명하고, 업무 용어·관측 단위·변수 뜻은 자료 안에서 먼저 정의합니다.

## 모듈의 책임

공개 실행기·Profile·DTO·JSON·7개 섹션 규약은 유지합니다. 등록 모듈은 266개이며, 내부 helper를 새 분석 기능으로 중복 등록하지 않습니다.

- 전체 Python 소스의 압축된 문장·분기·배열 표현을 일관된 다중 행 형식으로 정리했습니다. 기준은 Black 24.8, 줄 길이 88, Python3.7 출력 문법입니다. 포매터 실행 환경은 Python3.12입니다.
- 회귀 workflow는 원행 검증, 분할, 후보 선언 검증, 학습 내 CV 선택, 선택 이후 평가·DTO 구성을 분리합니다. 후보 선택 함수에는 최종 평가 자료를 전달하지 않습니다.
- 응용 모의 공통 실행부는 데이터·문항 순서만 관리합니다. 회귀·분류·시계열의 조합, 결과 표시는 별도 파일에서 담당합니다. 재사용 가능한 계산은 기존 src 모듈을 호출합니다.
- 전체 정밀 수치와 읽기용 출력을 분리합니다. 큰 행 위치·확률 배열을 출력 첫 화면에 나열하는 대신 핵심 비교표·계수·진단·실제 수치 결론을 먼저 제시합니다. 원 결과는 JSON에 보존합니다.

형식만 정리한 기존 소스의 구문 트리는 docstring 공백을 제외하고 이전과 같습니다. 회귀 workflow의 책임 분리는 별도 실행·경계·수치 동등성 검사로 검증합니다. 형식 정리와 책임 분리는 Git 커밋에서도 구분합니다.

## 모의고사의 읽는 순서

현재 모의 자료는 종합 모의1~15회·생존분석 모의, 총16묶음211문항입니다. 각 묶음에는 다음 자료가 있습니다.

| 자료 | 제공 내용 | 읽는 기준 |
| --- | --- | --- |
| 자료안내.md | 상황·한 행의 의미·판단 목적·모든 CSV 열의 뜻 | 도메인 지식 없이도 목표/입력/식별자/시간을 구별 |
| 문제지 PDF | 응시 안내→대문항별 자료 이해→수행 과제 | 조건·단위·배점을 먼저 확인하고 해설을 보지 않고 수행 |
| 실행 노트북 | 같은 문제→핵심 산출물·근거→읽기 쉬운 코드→표·그림 | 전체를 위에서 아래로 실행하고 실제 결과와 가정을 연결 |
| 해설.md | 풀이 근거·실제 실행 수치·결과 해석 기준 | 숫자를 정답 문구에 끼워 맞추지 않고 개선 실패도 보고 |
| 분석코드.py | 노트북과 같은 순차 실행 코드 | 임의 작업 디렉터리에서 실행해도 해당 자료 폴더를 사용 |
| 실행결과/*.json | 전체 정밀값·원행·경고·선택 이력 | 표시용 반올림·행 요약으로 생략한 내용을 재확인 |

문제지는 대문항마다 자료 안내와 과제를 분리합니다. 수치 표는 헤더와 열 역할을 명시하고, 본문과 과제에는 충분한 줄 간격을 둡니다. 현재16개 문제지는 각7쪽입니다. 문항 수·배점·입력 CSV·후보·분할·시드·검정 조건은 유지합니다.

## 도메인 설명의 범위

- 배치·수율·직렬 공정·병목·연체·청구 이상·중도절단·위험집합처럼 분석에 필요한 용어를 먼저 설명합니다.
- 포지션 코드·피트/인치·범주 코드·사건0/1·변환 단위를 자료 사전에 명시합니다. 단위가 제공되지 않은 통화·기간을 새로 추정하지 않습니다.
- 응용 모의의 Feature는 실제 면적·가격 등의 원 측정값이 아닌 고정 기준 대비 편차 지수입니다. 음수가 가능한 이유와 표본 전체에서 미리 표준화한 값이 아니라는 점을 구분합니다.
- c1~c4는 의미를 더 추정할 수 없는 가상 사전 신호입니다. 산업의 실측 위험 지표라고 설명하지 않습니다.
- 회귀·분류·시계열 CSV의 target은 이름만 같고 관측 대상·단위가 서로 다릅니다. 특히 횟수 회귀와 별도 연속 수요 시계열을 혼동하지 않습니다.
- 불명확한 특정 변수의 중복 관계를 사실로 단정하지 않고 자료에서 점검하도록 안내합니다. 합성 자료로 현장 인과·안전·투자 성과를 확정하지 않습니다.

## 생성과 검증

학습 환경의 requirements와 함께 작성용 `requirements-dev-py312.txt`를 설치합니다. Black은 생성 코드의 서식을 정리할 때 사용하며 분석 모듈 실행 의존성은 아닙니다.

```bash
python -m pip install -r 기출문제/requirements-py312.txt -r requirements-dev-py312.txt
python tools/exams/improve_mock_readability.py
# 실제 풀이 실행 이후 수치 해설만 갱신
python tools/exams/improve_mock_readability.py --answers-only
python tools/exams/audit_mock_readability.py
python -m black --check --workers 1 src 기출문제/모의고사/공통
```

생존분석의 실제 실행에는 해당 폴더 또는 도메인 requirements도 필요합니다. 실행기를 사용할 때는 `python tools/exams/execute_notebooks.py <노트북 경로>`로 각 노트북을 독립 실행합니다. PDF·자료 사전 생성은 같은 입력에서 같은 파일을 만들며, 해설은 실제 실행 후 갱신합니다. 기존 생성기의 후처리에도 같은 편집 규칙을 연결했습니다.

검사는 변수 설명 누락·같은 문제의 PDF/풀이 대응·문항 순서·독립 코드 일치·실행 오류·A4 경계·폰트 글자 누락을 확인합니다. 수치 답안은 변경 전 전체41묶음과 별도로 대조합니다. 실행 결과와 레이아웃 검수는 [검증 기록](VALIDATION.md), 각 모의의 검증 JSON에서 확인합니다.
