# 저장소 파일 명세 기준

전체 저장소 파일을 점검하되, 실행 모듈·설정·학습 자료의 형식을 구분합니다. Python 모듈에는 아래 헤더를 적용하며, 데이터 파일에 Python 문자열을 넣거나 JSON/YAML 스키마를 변경하지 않습니다.

| 파일 종류 | 점검·명세 방법 |
| --- | --- |
| 모든 `.py` | src·패키지 초기화·내부 helper·skeleton·examples·tests·tools·문제 풀이 코드·참조 코드까지 표준 모듈 헤더 검사 |
| JSON·YAML·TOML | 설정/문항/결과 스키마와 연결 문서 유지. JSON에는 주석을 넣지 않음 |
| Markdown | 기능·입력·출력·가정·실패 조건을 분야별 문서로 연결 |
| Notebook | 기존 문제·설명·실행 셀 유지. 공통 계산 모듈과 생성 도구의 Python 명세 적용 |
| CSV·TXT·압축 원자료·이미지·PDF·폰트 | 원자료/학습 결과의 내용과 형식 유지; 모듈 헤더를 삽입하지 않음 |

Python 헤더에는 파일명·실제 역할, 설명, 분석 가정, 작성 정보, 변경 이력이 있습니다. 작성자 표기는 `김재현(Finn) (penguin.klg@gmail.com)`으로 통일했습니다. 기존 작성일·기능 설명·분석 가정·라이선스·이력은 보존하며, 헤더를 새로 문서화한 파일은 적용일을 기록합니다. 실행 코드의 클래스/함수 설명과 원래 수식은 그대로 둡니다.

```python
"""
================================================================================
module.py - 해당 파일이 제공하는 구체적 기능
================================================================================
설명:
    - 입력과 처리 과정 및 결과의 역할.
분석 가정:
    - 이 파일의 자료·실행·계산 조건.
작성 정보:
    - 작성자: 김재현(Finn) (penguin.klg@gmail.com)
    - 작성일: YYYY-MM-DD
    - 라이선스: Proprietary
변경 이력 (Revision History):
    DATE        AUTHOR          VERSION   DESCRIPTION
    YYYY-MM-DD  김재현(Finn)     v1.0.0    변경 내용
================================================================================
"""
```

표준화 도구는 `python tools/exams/module_spec.py --write`, 전수 검사는 `python tools/exams/module_spec.py --check`입니다. [검사·생성 구현](../tools/exams/module_spec.py)은 Git 추적 파일 및 새 비무시 파일을 종류별로 집계하고 모든 Python 파일을 검사합니다. shebang·인코딩 선언과 future import 순서를 보존하며, 재적용 시 변경이 없어야 합니다.

문제지/풀이 생성 도구는 Python 실행 파일을 쓸 때 `write_python()`을 사용합니다. 기존 표준 헤더가 있는 파일을 재생성할 때는 그 파일의 설명·이력을 유지합니다. 새 파일은 실제 역할을 작성한 후 헤더 검사를 실행하세요. CI의 Source readability 작업에서도 같은 검사를 실행합니다.

전체 파일 점검은 기능의 정확성을 새로 입증했다는 뜻이 아닙니다. 실행 동작의 보존은 AST 비교와 기존 회귀 테스트로, 파일 저장·복원 기능은 해당 입력 계약 테스트로 별도 검증합니다. [검증 기록](VALIDATION.md), [전체 기능 카탈로그](ANALYSIS_CATALOG.md), [데이터 로딩·저장](DATA_LOADING.md)을 함께 확인하세요.
